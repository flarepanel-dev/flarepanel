# Self-hosting

FlarePanel is one codebase: the hosted service and a self-hosted install run the same code, the same dashboard and accept the same SDKs. You can self-host it in two ways.

## Choose how to self-host

| | Cloudflare | Your own server |
|---|---|---|
| Runs on | Workers, Durable Objects, D1, R2, Queues in **your** Cloudflare account | Docker on one Linux machine: ClickHouse, Redis, Redpanda, the API and the dashboard |
| You operate | Nothing: no servers or databases | The machine, its disk and its backups |
| You need | Workers Paid plan and a domain on Cloudflare DNS | 4 GB of memory or more, two hostnames |
| Cost | Cloudflare usage | The server |
| Guide | [Deploy to Cloudflare](/self-hosting/deploy) | [Deploy to your own server](/self-hosting/server) |

Pick Cloudflare when you want nothing to maintain and traffic that can grow without resizing a machine. Pick your own server when your data must stay on hardware you control, or you already run Docker hosts.

A few things differ between the two:

| | Cloudflare | Your own server |
|---|---|---|
| Connect Cloudflare (no-code crawler import) | Yes | No: report crawlers from your server or edge |
| Raw event archive | R2 | ClickHouse keeps everything |
| Event retention | A setting | A ClickHouse TTL |
| Backups | D1 and Durable Object point-in-time recovery | Backup and restore scripts |
| Visitor location | Cloudflare's edge | A GeoLite2 database built into the image |
| Email | Cloudflare Email | SMTP or Resend |

Everything else is the same on both: reports, funnels, retention, sessions and replay, profiles, cohorts, realtime, bots and AI crawlers, public widgets, AI answers and observability, imports, exports, Search Console, the REST API and MCP.

The rest of this page describes the Cloudflare install.

## Self-hosted and hosted

Like OpenPanel, one switch decides which one an install is: `SELF_HOSTED`, set on both Workers ([Deploy](/self-hosting/deploy#point-it-at-your-domains)).

| | Self-hosted (`SELF_HOSTED` set) | Hosted flarepanel.dev |
|---|---|---|
| Price | Free; you pay Cloudflare for what you use | Plans by monthly events, 30-day free trial |
| Features | Everything | Everything, in every plan |
| Events | No limit | Your plan's events; email at 80%, never an overage charge |
| Session replay | Every organization, 10,000 recorded sessions a month each by default (changeable) | Trial: 500 a month; plans: one recorded session per 100 plan events (1,000 to 100,000) |
| AI chat | With your own OpenAI or Anthropic key | Included |
| Billing pages | Hidden | Shown |

Limits exist so that nobody's bill grows by surprise: on Cloudflare every request and every stored replay chunk is metered. Set a [budget alert](/self-hosting/operations#alerts-in-your-cloudflare-account) on your account as well.

## What you need

- A Cloudflare account on the **Workers Paid** plan. The API bundle is about 4.6 MB compressed, above the free plan's 3 MB limit.
- A domain on Cloudflare DNS for the API and dashboard, for example `api.example.com` and `analytics.example.com`.
- [Bun](https://bun.sh) and the repository.

## What gets created

| Resource | Used for |
|---|---|
| Worker `flarepanel-api` | Tracking, the dashboard API, auth, jobs |
| Worker `flarepanel-dashboard` | The dashboard |
| D1 database | Accounts, organizations, projects, clients |
| D1 database `flarepanel-geo` (optional) | IP ranges for locating server-side events and the IP lookup tool (DB-IP City Lite) |
| Durable Objects | One per project: events, sessions, rollups, live sockets; plus rate limits and locks |
| R2 bucket | Raw event archive, AI prompt text, import copies (optional; without it events are kept 30 days and imports are unavailable) |
| Queues | Background jobs and their dead-letter queue |
| Email Service binding | Account emails and sign-up verification (optional) |
| Worker Loader binding | Runs JavaScript webhook templates in a sandboxed Dynamic Worker: no network, 50 ms CPU. One template counts as one Dynamic Worker a day (1,000 a month included) |

Deploy it in two clicks, or step by step: see [Deploy to Cloudflare](/self-hosting/deploy).
