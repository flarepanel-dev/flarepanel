# Architecture

```
SDK ─► POST /track (Worker)
         client auth, schema, bot check, geo from request.cf,
         1 s duplicate check in the Cache API, per-IP rate limit
       ─► ProjectEventsDurableObject (one per project, SQLite)
         device and session ids, the event pipeline,
         group commit (200 events or 500 ms), then answers
       ◄─ { deviceId, sessionId }

alarm: close idle sessions (session_end), checkpoint,
       archive to R2 every 10 minutes, move quiet AI traces'
       text to R2, apply retention
```

## Per-project Durable Object

Each project has one Durable Object holding:

- **chunks**: events as gzip-compressed JSON, one row per group commit. These are the source of truth.
- **daily** and **dims**: per-day totals (visitors as HyperLogLog, sessions, bounces, duration, page views, revenue) and per-day counts by page, source, place and device for the overview.
- **sessions** and **identities**: live sessions checkpointed for restarts, and profiles.
- **groups** and **cohort_members**: groups with their properties, and the stored members of each cohort (recomputed every 30 minutes).
- **ai_events**: one row per AI call (cost, tokens, latency, errors, a short preview); prompt and response text waits in **ai_content** until the trace is quiet, then moves to R2.
- **gsc_daily**, **gsc_pages_daily**, **gsc_queries_daily**: Search Console numbers per day, page and query.
- **import_staging**: an import's events while it runs, before they are committed in time order.
- **replay_sessions**: which sessions have a replay (the chunks are in R2).
- **bot_events**: recent bot hits (kept out of analytics), at most 5,000 a day, for 30 days.

Reports, the REST API, the MCP server and the chat assistant all read the same Durable Object, so every page answers from one place.

Rollups live in memory and are written at checkpoints. After a restart, everything newer than the last checkpoint is rebuilt from chunks, so nothing is counted twice or lost.

## R2 archive

Raw events are copied to R2 as newline-delimited JSON, one object per project and hour:

```
v1/events/project_id=<id>/date=YYYY-MM-DD/hour=HH/<firstChunk>-<lastChunk>.ndjson.gz
```

The same bucket holds each AI trace's prompt and response text (`ai/<project>/<trace>.json.gz`), session replay chunks (`replays/<project>/<session>/<start>-<end>-<index>.json.gz`; both removed after 30 days by lifecycle rules), failed jobs (`dead-letters/`) and the copies an import reads (`imports/<project>/<import>/`, removed when it ends).

Recent events stay in the Durable Object for 90 days by default (`FLAREPANEL_EVENT_RETENTION_DAYS`); R2 keeps everything. Reports that reach further back read the older hours from the R2 archive (at most 3,000 archive files per report, so very long ranges on very busy projects show what was read).

## D1

Accounts, organizations, members, projects, clients and settings live in D1 through Prisma's D1 adapter. D1 has no interactive transactions, so writes that must happen together are sent as one batch.

## IP geolocation

A second D1 database, `flarepanel-geo`, holds DB-IP's City Lite ranges: `geo_ranges_<n>` (16-byte start and end keys, IPv4 as `::ffff:a.b.c.d`) and `geo_locations_<n>`. A lookup is one indexed query for the last range starting at or below the address, cached a day. Each monthly refresh loads the next `<n>` and then switches, so lookups never see half a load. IP geolocation by [DB-IP](https://db-ip.com).

## Background jobs

Jobs run on Cloudflare Queues; a Cron Trigger every minute enqueues the ones that are due: Search Console sync (daily), cohort refresh (every 30 minutes), insights (daily), S3/GCS exports (every minute, behind a per-export position in each project's Durable Object), and account emails. Imports run as a chain of short queue steps, each well inside a Worker's CPU limit.

## Live dashboard

`/live/events/:projectId` and `/live/visitors/:projectId` WebSockets are checked for session and project access by the Worker, then held by the project's Durable Object with hibernation, so an open dashboard costs nothing while nothing happens.
