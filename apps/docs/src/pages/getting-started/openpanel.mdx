# Coming from OpenPanel

FlarePanel keeps OpenPanel's tracking protocol, so the OpenPanel SDKs work unchanged. Create a project in FlarePanel, then change two things: the **client ID** and the **API URL**.

:::code-group

```ts [JavaScript]
import { OpenPanel } from '@openpanel/web';

export const op = new OpenPanel({
  clientId: 'YOUR_FLAREPANEL_CLIENT_ID',
  apiUrl: 'https://api.flarepanel.dev', // [!code hl]
  trackScreenViews: true,
});
```

```tsx [Next.js]
import { OpenPanelComponent } from '@openpanel/nextjs';

<OpenPanelComponent
  clientId="YOUR_FLAREPANEL_CLIENT_ID"
  apiUrl="https://api.flarepanel.dev"
  scriptUrl="https://flarepanel.dev/op1.js"
  trackScreenViews={true}
/>
```

```html [Script tag]
<script>
  /* ...the same window.op stub... */
  window.op('init', { clientId: 'YOUR_FLAREPANEL_CLIENT_ID' });
</script>
<script src="https://flarepanel.dev/op1.js" defer async></script>
```

:::

The script tag version needs no `apiUrl`: FlarePanel's `op1.js` sends to `https://api.flarepanel.dev` by default.

## What carries over

| | |
|---|---|
| `track`, `identify`, `increment`, `decrement`, `revenue` | Same calls and payloads |
| Screen views, outgoing links, `data-track` attributes | Same options |
| Server SDKs with a client secret | Same headers (`openpanel-client-id`, `openpanel-client-secret`) |

Existing OpenPanel data is not imported; FlarePanel can import history from Umami, Mixpanel and Amplitude under a project's **Settings → Imports**. See [What works today](/getting-started/status) for the full list.

You can also switch to FlarePanel's own packages on npm (`@flarepanel/web`, `@flarepanel/nextjs`, `@flarepanel/sdk` and the rest). They have the same API, export both the `OpenPanel` and `FlarePanel` names, and send to `https://api.flarepanel.dev` without an `apiUrl`.
